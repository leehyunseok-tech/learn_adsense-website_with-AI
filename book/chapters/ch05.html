PART 3 · 화면부터 서버리스 기능까지

5

v0로 화면 설계하고 Claude Code로 옮기기

이 장에서는 사이트의 보이는 부분, 즉 화면 껍데기를 먼저 만듭니다. 터미널에서 Claude Code에게 곧바로 "이런 사이트를 만들어줘"라고 시키기보다, v0라는 AI 빌더로 화면 구조를 먼저 잡는 쪽이 훨씬 효율적입니다. 이 장을 마치면 우리 사이트의 첫 화면이 실제 프로젝트 안에 들어와 있을 것입니다.

약 15분 예제 2개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • v0에게 프롬프트로 홈페이지 화면 구조를 그리게 할 수 있다.
  • v0 결과물을 다운로드해 기존 프로젝트에 Claude Code로 이식할 수 있다.
  • 화면을 다듬을 때 v0와 Claude Code의 역할을 구분해 쓸 수 있다.

5.1 v0에게 화면을 프롬프트로 그리게 하기

사이트의 보이는 부분(껍데기)을 먼저 만듭니다. 저자 경험상 바로 Claude Code에게 "이런 사이트 만들어줘"라고 시키는 것보다, AI 빌더로 화면 구조를 먼저 잡는 편이 훨씬 효율적입니다.

[개념] v0

v0는 프롬프트만으로 Next.js와 Tailwind 기반의 실제 배포 가능한 프로덕션 코드를 생성해 주는 AI 화면 빌더입니다.

lovable, bolt 같은 유사 서비스도 있지만, 저자는 v0의 생성 품질이 더 높다고 판단해 애용합니다. https://v0.app/ 에서 바로 사용할 수 있으며, 무료 한도 안에서도 초기 디자인과 구조를 잡는 정도는 충분합니다.

[비유] 💡 이렇게 생각해 보세요

설계도 없이 집을 짓지 않는 것처럼, 화면도 초안 없이 바로 코드를 짜기 시작하면 나중에 뜯어고칠 곳이 많아져요. v0에게 먼저 화면 초안을 맡기는 건, 목수를 부르기 전에 건축가에게 설계도부터 받아 두는 것과 같아요.

[주의] v0에서 충분히 다듬지 않고 넘기는 함정

v0의 첫 결과물은 완성본이 아니라 출발점입니다. 여기서 대충 만족하고 바로 Claude Code로 넘기면, Claude Code에서 다시 프롬프팅해야 할 일이 훨씬 많아집니다. 저자도 완성도가 떨어졌던 졸라맨 캐릭터를 v0 안에서 반복해서 다듬은 뒤에야 넘겼습니다.

5.2 v0 결과물을 다운로드해 프로젝트에 이식하기

이번 예제 사이트인 "날씨 기반 옷차림 추천 사이트"의 홈페이지를 v0에게 그리게 해 보겠습니다. 저자가 실제로 입력했던 프롬프트를 그대로 옮겨 보겠습니다.

[비유] 🔧 이렇게 생각해 보세요

v0 결과물을 그대로 기존 프로젝트 위에 덮어쓰는 건, 새로 산 가구를 조립 설명서도 안 보고 원래 있던 방에 억지로 밀어 넣는 것과 같아요. 자리를 맞추려면 결국 기존 방 구조(프로젝트 설정)를 아는 사람이 다시 배치를 해줘야 해요.

[AI에게] AI에게 이렇게 시켜보세요

우리 서비스의 주 사용자 타겟은 내일 날씨, 이번주 날씨, 기온별 옷차림을 검색하는 유저들이고, 유저에게 트렌디함/편함/자주 들어오고싶은 인상을 주고 싶어. 홈페이지('/')에 사용할 컴포넌트를 만들어줘. 아래 정보가 포함되어야 해. - 오늘의 날씨 정보 (위치: 맨 왼쪽부터, 화면의 약 65%~70% 차지) - 활동지수(Activity Score): 80점 이상 실외활동하기 좋은 날씨(적절한 문구 필요), 80점 미만 실내활동하기 좋은 날씨(적절한 문구 필요) — 위치: 오늘의 날씨 정보 오른쪽 영역 상단 - 졸라맨 캐릭터에 옷 입혀서 오늘의 기온/날씨에 따른 옷차림 추천 — asset으로 반팔티, 반바지, 바람막이, 후드티, 패딩, 코트 등을 만들어서 조합 가능하게 해줘 (위치: 활동지수 아래)

이런 답이 오면 정상 — 왼쪽에 오늘의 날씨, 오른쪽 위에 활동지수, 그 아래 졸라맨 옷차림 추천이 배치된 홈페이지 컴포넌트가 나옵니다. 첫 결과물은 초안일 뿐이므로, 마음에 들 때까지 이어서 수정 프롬프트를 계속 보내야 합니다.

다 다듬었다면 아래 순서로 기존 프로젝트에 옮깁니다.

  1. v0 화면 오른쪽 위의 "Download ZIP" 버튼을 눌러 완성본을 내려받습니다.
  2. 압축을 풀고, 3장에서 만든 기존 프로젝트(skeleton) 폴더 옆에 둡니다.
  3. Claude Code에게 기존 프로젝트 구조를 보존하면서 이 디자인만 옮겨 달라고 요청합니다.
  4. 새로 만드는 컴포넌트나 디자인은 기존 화면과 이질감이 없도록 만들어 달라고 함께 요청합니다.

[AI 함정] AI가 여기서 틀립니다

v0가 만들어 준 프로젝트를 압축 해제해 기존 skeleton 프로젝트 폴더 위에 그대로 복사하면, 서로 다른 package.json이나 설정 파일이 충돌합니다. 파일 이름이 같아 보여도 내부 의존성 목록이 달라, 그대로 덮어쓰면 npm install이 깨지기 쉽습니다.

[X] 이렇게 옮기면 위험 
# v0 압축을 그대로 풀어서 덮어쓰기
skeleton/package.json        ← v0의 package.json으로 통째로 교체됨
skeleton/tailwind.config.*   ← v0 설정으로 통째로 교체됨
문제 
· 기존 프로젝트에 맞춰 둔 배포 설정(4장의 Cloudflare 연동 등)이 사라짐
· npm install 시 의존성 충돌로 에러 발생
[O] Claude Code에게 이렇게 요청 
v0 폴더의 디자인(컴포넌트, 스타일)만 우리 프로젝트로
옮겨줘. package.json이나 배포 설정 같은
기존 파일 구조는 그대로 유지해줘.

이걸 잡아낸 개념 — 5.1절에서 강조한 "설계도는 v0, 조립은 Claude Code"라는 역할 구분입니다. v0는 화면 디자인의 출발점일 뿐, 프로젝트 설정까지 통째로 가져올 대상은 아닙니다.

이 장에서 배운 것

  • v0에게 프롬프트로 홈페이지 화면 초안을 그리게 했다.
  • v0 결과물을 충분히 다듬은 뒤 Download ZIP으로 내려받았다.
  • Claude Code에게 기존 프로젝트 구조를 지키면서 디자인만 이식해 달라고 요청했다.

설계도는 v0에서 먼저 그리고, 조립과 이식은 Claude Code에게 맡기는 것이 지름길입니다.

연습문제

1. 바로 Claude Code에게 "이런 사이트 만들어줘"라고 시키지 않고 v0를 먼저 쓰는 이유는 무엇인가요? 쉬움

정답 보기

AI 빌더인 v0로 화면 구조를 먼저 잡는 편이 바로 Claude Code에 맡기는 것보다 훨씬 효율적이기 때문입니다. 설계도 없이 집을 짓지 않는 것과 같은 이치입니다.

2. v0의 첫 결과물을 받자마자 바로 Claude Code로 넘기면 안 되는 이유는 무엇인가요? 보통

정답 보기

v0의 첫 결과물은 완성본이 아니라 출발점이기 때문입니다. 충분히 다듬지 않고 넘기면 Claude Code에서 다시 프롬프팅해야 할 일이 훨씬 많아집니다.

3. v0에서 받은 압축 파일을 기존 skeleton 프로젝트 위에 그대로 풀어서 덮어쓰면 어떤 문제가 생기고, 어떻게 피해야 하나요? 어려움

정답 보기

package.json이나 배포 설정 같은 파일이 v0의 것으로 통째로 바뀌어, 4장에서 맞춰 둔 Cloudflare 배포 설정이 깨지거나 npm install이 실패할 수 있습니다. Claude Code에게 기존 프로젝트 구조는 유지한 채 디자인만 옮겨 달라고 요청해야 합니다.
