Claude Code와 Github로 도구 갖추기

이 장에서는 실습에 쓸 두 가지 도구를 준비합니다. Claude Code는 터미널에서 대화로 코드를 대신 써주는 AI 코딩 도구이고, Github는 그렇게 만든 코드를 안전하게 저장하는 곳입니다. 이 두 가지만 갖추면 다음 장부터 바로 실습을 시작할 수 있습니다.

약 15분 예제 2개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • Claude Code를 설치하고 로그인해 터미널에서 바로 쓸 수 있다.
  • Github로 나만의 Private 저장소를 만들 수 있다.
  • 프로젝트 폴더에서 Claude Code를 실행해 AI에게 프로젝트 구성을 물어볼 수 있다.

3.1 Claude Code 설치하고 첫 대화 나누기

Claude Code는 Anthropic이 만든 AI 코딩 도구로, 별도의 편집기 화면 없이 터미널(명령 프롬프트)에서 대화하듯 코드를 작성·수정합니다. 파일을 하나씩 열어보지 않아도 "이런 기능을 만들어줘"라고 말하면 프로젝트 전체를 훑어보고 필요한 파일을 스스로 찾아 고칩니다. 이 책의 모든 실습은 Claude Code 위에서 이뤄집니다.

[개념] Claude Code

Claude Code는 터미널 위에서 동작하는 AI 코딩 에이전트로, 자연어 지시만으로 파일을 읽고 쓰고, 명령어를 실행하고, Git 작업까지 대신 처리해 줍니다.

[비유] 💡 이렇게 생각해 보세요

Claude Code는 전화로 일을 맡기는 유능한 원격 팀원이에요. 화면에 파일 목록을 눈으로 보여주진 않지만, "프로젝트 전체를 살펴보고 이 기능을 추가해줘"라고 말하면 알아서 관련 파일을 다 찾아 고쳐 놓아요. 결과만 터미널에 차분히 보고해 주는 느낌이에요.

설치 방법은 두 가지입니다. 가장 간단한 방법은 터미널(PowerShell)에서 아래 명령어 한 줄을 실행하는 것으로, Node.js가 미리 깔려 있지 않아도 됩니다. 

irm https://claude.ai/install.ps1 | iex

이미 Node.js(18 이상)가 설치되어 있다면 npm으로도 설치할 수 있습니다. 

npm install -g @anthropic-ai/claude-code

설치가 끝나면 아래 순서로 첫 실행을 확인합니다.

  1. 터미널에서 실습용 프로젝트 폴더로 이동합니다.
  2. claude라고 입력하고 엔터를 누릅니다.
  3. 처음 실행하면 브라우저가 열리며 로그인을 요구합니다. Claude 계정(Pro·Max 요금제에 포함된 사용량을 쓰거나, Anthropic Console의 API 크레딧을 충전해 쓸 수 있습니다)으로 로그인합니다.
  4. 로그인이 끝나면 터미널 안에 대화창이 뜨고, 바로 말을 걸 수 있는 상태가 됩니다.

[주의] 아무 폴더에서나 실행하는 함정

claude는 실행한 위치(현재 폴더)를 기준으로 파일을 찾고 수정합니다. 엉뚱한 폴더에서 실행하면 원하는 프로젝트가 아니라 그 폴더 전체를 대상으로 작업하게 됩니다. 작업을 시작하기 전엔 항상 cd로 실습 폴더 안에 들어와 있는지 먼저 확인하세요.

[비유] 🔧 참고 — Cursor를 쓰고 싶다면

Cursor처럼 파일 목록과 대화창을 한 화면에서 보는 편집기형 AI 도구를 더 편하게 느끼는 사람도 있어요. cursor.com에서 설치할 수 있고, 이 책에 나오는 프롬프트는 Cursor의 채팅창에 그대로 붙여 넣어도 거의 똑같이 동작해요. 다만 이 책은 이후로 Claude Code 기준으로 설명을 이어갈게요.

3.2 Github와 Github Desktop으로 코드 저장소 만들기

Github(깃허브)는 내가 만든 파일과 코드를 안전하게 저장하고 버전별로 관리하는 온라인 저장소입니다. Claude Code로 작업한 내용은 컴퓨터에도 저장되지만, Github에 올려두면 인터넷에서도 안전하게 보관됩니다. 다른 컴퓨터에서 이어 작업하거나 파일이 사라져도 다시 내려받을 수 있습니다.

[비유] 🔧 이렇게 생각해 보세요

Github는 코드를 위한 구글 드라이브라고 생각하면 편해요. 내 컴퓨터에 있는 파일을 클라우드에 올려두면 어디서든 꺼내 쓸 수 있는 것처럼, Claude Code로 작업한 코드를 Github에 올려두면 다른 컴퓨터에서도, 심지어 컴퓨터가 고장 나도 그대로 이어받을 수 있어요.

저장소를 만드는 방법은 두 가지입니다. Claude Code에게 그대로 시키거나, GUI가 익숙하다면 Github Desktop을 따로 설치해도 됩니다. 이 책은 이후로 Claude Code에게 맡기는 방법을 기준으로 설명합니다.

  1. github.com에서 회원가입을 합니다.
  2. 터미널에서 실습용 프로젝트 폴더로 이동해 claude를 실행합니다.
  3. Claude Code에게 "이 폴더를 git 저장소로 만들고, Github에 Private 저장소를 만들어서 올려줘"라고 요청합니다. 처음 요청할 때 Github 로그인 창이 뜨면 승인합니다.
  4. github.com에서 방금 만든 repository가 실제로 Private로 표시되는지 확인합니다.
  5. 이후 코드를 수정할 때마다 "변경사항을 커밋하고 푸시해줘"라고 말하면 됩니다.

Github Desktop을 쓰고 싶다면 — docs.github.com의 안내를 따라 설치한 뒤, 로그인 → Publish repository(Keep this code private 반드시 체크) → 파일 추가 → commit → push 순서로 진행하면 동일한 결과를 얻습니다.

[AI 함정] AI가 여기서 틀립니다

Claude Code에게 그냥 "Github 저장소 만들어줘"라고만 하면, Public/Private을 지정하지 않았을 때 기본값인 Public으로 만들어버리는 경우가 있습니다. Public이면 누구나 코드를 볼 수 있고, 나중에 API 키가 담긴 파일을 실수로 커밋하면 그 키가 인터넷에 그대로 노출됩니다.

[X] 애매한 요청 
나: Github 저장소 만들어줘

Claude Code: gh repo create weather-app
             --source=. --push
문제 
· --private 옵션이 없어 기본값인 Public으로 생성됨
· 이후 커밋한 .env 파일의 API 키가 그대로 인터넷에 노출됨
[O] 명확한 요청 
나: Github에 Private 저장소로 만들어서 올려줘

Claude Code: gh repo create weather-app
             --private --source=. --push

이걸 잡아낸 개념 — 저장소를 만들어달라고 할 때 "Private"이라는 단어를 직접 넣어 요청하는 습관입니다. 6장에서 실제 API 키를 다룰 때 이 습관이 그대로 쓰입니다.

3.3 Claude Code에게 프로젝트 구성 물어보기

저장소까지 만들었으니, 이제 그 폴더 안에서 claude를 실행해 프로젝트를 파악할 차례입니다. Claude Code는 파일을 눈으로 보여주는 대신, 물어보면 알아서 폴더를 훑어보고 말로 정리해 줍니다. /init이라는 슬래시 명령을 입력하면 프로젝트 구조를 스스로 분석해 CLAUDE.md라는 요약 파일을 만들어 주는데, 이후 대화마다 이 파일을 참고해 더 일관된 답을 줍니다.

[AI에게] AI에게 이렇게 시켜보세요

이 프로젝트 구성을 설명해줘. [내 환경] 방금 Github 저장소 폴더 안에서 claude를 실행했어. [하고 싶은 것] 이 프로젝트에 어떤 파일과 폴더가 있는지, 각각 무슨 역할을 하는지 알고 싶어. [꼭 지켜줘] - 처음 개발을 배우는 사람도 이해할 수 있게 쉬운 말로 설명해줘 - npm run dev와 npm run build가 각각 뭘 하는 명령어인지도 알려줘 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — 폴더와 파일 구조를 하나씩 짚어 주고, npm run dev는 "내 컴퓨터에서 미리 보기", npm run build는 "인터넷에 올릴 준비가 됐는지 확인하는 단계"라는 식으로 쉬운 비유를 곁들여 설명합니다.

개발하면서 자주 쓰는 명령어는 두 가지입니다. npm run dev는 로컬 컴퓨터에서 서버를 실행해 지금 만든 화면이 제대로 동작하는지 확인하는 명령어입니다. npm run build는 실제 인터넷에 배포하기 전, 배포 가능한 형태로 미리 완성해 보는 명령어입니다.

dev는 "내 컴퓨터에서 미리 보기", build는 "인터넷에 올릴 준비가 됐는지 확인하는 단계"라고 기억하면 됩니다. 이 두 명령어는 4장에서 실제로 눌러 보며 확인합니다.

이 장에서 배운 것

  • 터미널에서 Claude Code를 설치하고 로그인해 AI 코딩 환경을 갖췄다.
  • Claude Code에게 부탁해 Github Private 저장소를 만들고 commit, push까지 해봤다.
  • Claude Code에서 /init으로 프로젝트 구성을 파악하는 법을 익혔다.

Claude Code는 터미널에서 함께 일하는 AI 팀원이고, Github는 그 결과물을 안전하게 보관하는 저장소입니다.

연습문제

1. Claude Code를 처음 실행하면 무슨 일이 일어나며, 왜 그 과정이 필요한가요? 쉬움

정답 보기

브라우저가 열리며 로그인을 요구합니다. Claude 계정으로 내 사용량을 확인하고 인증하기 위해서입니다.

2. Claude Code에게 Github 저장소를 만들어달라고 할 때 반드시 함께 말해야 하는 단어는 무엇이고, 빠뜨리면 어떤 문제가 생기나요? 보통

정답 보기

"Private"이라는 단어를 명시해야 합니다. 빠뜨리면 기본값인 Public으로 만들어져 누구나 내 코드와 그 안의 API 키 같은 민감 정보를 볼 수 있게 됩니다.

3. Claude Code로 코드를 수정만 하고 커밋·푸시를 요청하지 않으면 나중에 어떤 문제가 생길 수 있나요? (4장의 Cloudflare 자동 배포와 연결해서 생각해 보세요) 어려움

정답 보기

commit은 "이 파일들로 작업을 완성하겠다"는 확정이고, push는 "그것을 Github에 올리겠다"는 뜻입니다. 이 두 단계를 하지 않으면 변경 내용이 Github.com에 반영되지 않으므로, 4장에서 연결할 Cloudflare 자동 배포도 새 버전을 감지하지 못해 옛날 화면이 계속 보이게 됩니다.
