8

방문자 분석하고 검색엔진에 등록하기

내 도메인으로 사이트를 열었어도, 누가 찾아오는지 모르면 답답합니다. 이 장에서는 방문자 데이터를 들여다보는 법과, 검색엔진에 사이트가 존재한다는 사실 자체를 알리는 법을 배웁니다.

약 25분 예제 2개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • 구글 애널리틱스를 사이트에 연동해 실시간 방문자와 유입 추이를 확인할 수 있습니다.
  • next-sitemap으로 동적 sitemap.xml을 만들어 검색엔진에 페이지 구조를 알릴 수 있습니다.
  • 구글 서치콘솔, 네이버 서치어드바이저, 다음 웹마스터에 사이트를 등록할 수 있습니다.

8.1 구글 애널리틱스로 방문자 들여다보기

사이트를 운영할 때는 얼마나 많은 사람이 방문했는지, 어디에서 들어왔는지, 홍보가 실제로 효과가 있었는지를 아는 것이 매우 중요합니다. 이를 알려주는 대표 도구가 Google Analytics(구글 애널리틱스)입니다.

구글 애널리틱스는 완전히 무료로 사용할 수 있고, 개인 프로젝트나 소규모 서비스에는 무제한 데이터 분석만으로도 충분합니다. 지금 이 순간 몇 명이 접속해 있는지, 어떤 페이지를 보고 있는지도 실시간으로 확인할 수 있습니다.

[개념] 추적 코드(tracking code)

사이트에 심어두면 방문 기록을 구글 애널리틱스 서버로 전송해주는 짧은 스크립트입니다.

[비유] 💡 이렇게 생각해 보세요

구글 애널리틱스는 사이트에 설치한 CCTV예요. 방금 인스타그램에 홍보 글을 올렸더니 방문자 수가 확 늘었네, 하는 걸 그래프로 바로 확인할 수 있어요. 주말보다 평일에 사람이 더 많이 들어오는 것도 CCTV 녹화본을 돌려보듯 알 수 있어요.

연동 방법은 다음과 같습니다. analytics.google.com에 접속해 "측정 시작"을 누르고, 계정 이름과 속성명을 입력합니다. 업종은 마땅한 게 없으면 "온라인 커뮤니티"로 해도 무방합니다. 비즈니스 목표는 "트래픽 파악", 플랫폼은 "웹"으로 고르고 구매한 도메인 주소를 입력하면 추적 코드가 발급됩니다.

이 추적 코드를 사이트에 넣는 작업은 Claude Code에게 그대로 위임하면 됩니다. 커밋하고 푸시하면 배포가 시작되고, 배포가 끝난 뒤 "설치 테스트" 버튼을 누르면 데이터 수집이 활성화됩니다. 이 시점부터 실시간 접속자 수가 화면에 보이기 시작합니다.

[주의] 정적 sitemap만 만들어두고 안심하는 함정

sitemap.xml을 한 번 손으로 써서 올려두면, 나중에 페이지가 추가돼도 검색엔진에 새 페이지가 반영되지 않습니다. 이 문제는 다음 8.2절에서 더 자세히 다룹니다.

8.2 sitemap.xml로 검색엔진에 지도 건네기

검색엔진은 사이트를 자동으로 탐색(크롤링)하지만, 페이지가 많으면 모든 페이지를 정확히 찾기 어렵습니다. sitemap.xml은 "우리 사이트에 이런 페이지들이 있어요"라고 알려주는 지도 역할을 합니다. 이 파일이 있으면 검색엔진이 사이트 구조를 빠르고 정확하게 이해하고, 새 페이지도 더 빨리 검색 결과에 반영할 수 있습니다.

[비유] 🔧 이렇게 생각해 보세요

sitemap.xml은 택배기사에게 건네는 아파트 동호수 지도예요. 지도가 없으면 택배기사가 건물을 한 채씩 다 뒤져야 하지만, 지도가 있으면 몇 동 몇 호에 뭐가 있는지 바로 찾아가요. 새로 이사 온 세대(새 페이지)도 지도에 적어둬야 택배가 와요.

정적 sitemap은 직접 써넣는 주소록이고, 동적 sitemap은 사이트가 스스로 최신 주소록을 만들어내는 방식입니다. 페이지가 자주 바뀌거나 추가되는 서비스라면 동적 sitemap으로 만들어야 검색엔진이 최신 상태를 반영할 수 있습니다.

[AI에게] AI에게 이렇게 시켜보세요

next-sitemap 패키지를 써서 우리 사이트에 동적 sitemap.xml을 만들어줘. [내 환경] - 배포한 도메인: 내가산도메인.com - 페이지가 앞으로도 계속 추가될 수 있는 구조야. [하고 싶은 것] - next-sitemap 패키지를 설치하고 설정 파일을 만들어서 빌드할 때마다 sitemap.xml이 최신 페이지 목록으로 자동 생성되게 해줘. - robots.txt에도 sitemap 위치가 연결되도록 해줘. [꼭 지켜줘] - sitemap 안의 주소가 전부 내가산도메인.com 기준으로 나오게 해줘. 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — 빌드 스크립트에 next-sitemap 실행 단계가 자동으로 포함되고, sitemap.xml 안의 모든 주소가 내 도메인 기준으로 나옵니다.

[AI 함정] AI가 여기서 틀립니다

검색엔진 소유권 확인은 서비스마다 방법이 조금씩 다른데, AI가 이를 뭉뚱그려서 잘못된 파일 경로나 잘못된 확인 방식을 알려주는 경우가 있습니다. 인증 화면에 오류 없이 "확인 중"만 뜨기 때문에 무엇이 잘못됐는지 바로 알아채기 어렵습니다.

프로젝트 루트(/)에 업로드하라고 안내
→ 실제로는 /public 경로에 있어야
   빌드 후에도 그대로 배포됨

· 소유확인 버튼을 눌러도 계속 "확인 실패"가 뜸
[O] 고친 방법 
네이버가 준 HTML 파일을

이걸 잡아낸 개념 — 8.3절에서 다루는 "각 검색엔진이 안내하는 정확한 경로를 그대로 따라야 한다"는 원칙입니다.

8.3 구글·네이버·다음에 사이트 등록하기

사이트를 만들면 가장 먼저 해야 하는 일 중 하나가 검색엔진 등록입니다. 등록하지 않으면 사람들이 검색해도 사이트가 보이지 않고, 등록하더라도 오랜 기간 노출되지 않을 수 있습니다. 등록은 "이 사이트가 존재한다"는 사실을 검색엔진에 알리는 절차입니다.

구글 서치콘솔은 search.google.com/search-console에서 "시작하기"를 누르고 도메인 주소를 입력해 소유권을 확인합니다. Cloudflare에 이미 연결된 도메인이라 실제 소유자인지 인증이 진행됩니다. 인증이 끝나면 Sitemaps 메뉴에서 https://구매한도메인주소/sitemap.xml을 제출합니다. 이때 배포가 성공한 상태여야 정상적으로 제출됩니다.

네이버 서치어드바이저는 searchadvisor.naver.com/console/board에서 HTML 확인 파일을 다운로드해 프로젝트의 /public 경로에 업로드한 뒤 배포합니다. 배포가 끝나면 소유확인 버튼을 누르고, 다시 접속하면 등록된 사이트가 보입니다. 이후 "사이트맵 제출"을 눌러 구글과 마찬가지로 sitemap을 제출합니다.

다음 웹마스터는 webmaster.daum.net/login에서 비밀번호를 임의로 설정한 뒤 로그인합니다. robots.txt 파일 하단에 안내된 텍스트를 기입해야 하는데, 이 작업도 Claude Code에게 위임한 뒤 배포하면 됩니다. 성공하면 화면에서 확인할 수 있고, "수집 요청"을 눌러 sitemap.xml을 수집 요청하면 됩니다.

이 장에서 배운 것

  • 구글 애널리틱스 추적 코드를 연동해 실시간 방문자와 유입 추이를 확인할 수 있게 됐습니다.
  • next-sitemap으로 동적 sitemap.xml을 만들어 새 페이지도 검색엔진에 자동으로 반영되게 했습니다.
  • 구글 서치콘솔, 네이버 서치어드바이저, 다음 웹마스터에 사이트와 sitemap을 등록했습니다.

사이트를 만들었으면 CCTV(애널리틱스)를 달고 지도(sitemap)를 검색엔진에 건네야 진짜로 발견됩니다.

연습문제

1. 구글 애널리틱스를 연동하면 무료로 확인할 수 있는 정보 두 가지를 쓰세요. 쉬움

정답 보기

실시간 방문자 수와 보고 있는 페이지, 그리고 일간·주간·월간 방문자 추이 등을 확인할 수 있습니다. 홍보 채널별 효과도 그래프로 시각적으로 비교할 수 있습니다.

2. 정적 sitemap.xml 대신 next-sitemap으로 동적 sitemap을 만들어야 하는 서비스는 어떤 특징을 가진 사이트인가요? 보통

정답 보기

페이지가 자주 추가되거나 바뀌는 서비스입니다. 정적 sitemap은 한 번 써두면 그대로 고정되어 새 페이지가 검색엔진에 반영되지 않지만, 동적 sitemap은 빌드할 때마다 최신 목록으로 다시 만들어집니다.

3. 네이버 서치어드바이저에서 소유확인용 HTML 파일을 업로드했는데 계속 확인에 실패한다면, 무엇을 가장 먼저 확인해봐야 할까요? 어려움

정답 보기

파일을 올린 경로가 맞는지 확인해야 합니다. 네이버가 요구하는 위치는 프로젝트의 /public 경로이며, 다른 곳에 올리면 배포 후에도 그 파일이 실제로 접근되지 않아 인증이 계속 실패합니다.
