PART 5 · 브랜딩과 수익화

9

파비콘과 링크 미리보기 꾸미기

지금 사이트는 브라우저 탭에 기본 아이콘이 뜨고, 링크를 공유하면 미리보기가 텅 비어 있습니다. 파비콘과 Open Graph는 코드 몇 줄로 끝나지만 사이트를 미완성에서 완성으로 바꾸는 첫인상 작업입니다.

약 15분 예제 2개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • favicon.io에서 우리 사이트만의 파비콘을 만들어 기본 아이콘과 교체할 수 있습니다.
  • Open Graph 메타 태그와 og-image를 넣어 카카오톡·페이스북 공유 미리보기를 완성할 수 있습니다.

9.1 파비콘 — 탭에 남는 첫인상

브라우저 탭 맨 왼쪽에 붙는 작은 아이콘을 파비콘(favicon)이라고 부릅니다. 사용자가 탭을 열 개씩 띄워 놓아도 파비콘 하나로 "아, 이게 우리 사이트구나"를 알아챕니다. 검색 결과나 즐겨찾기 목록에도 함께 노출되므로, 작은 이미지 하나가 사이트 전체의 인상을 좌우합니다.

새로 만든 사이트는 지금 프레임워크가 기본으로 붙여 준 아이콘(예를 들어 Vercel 로고)을 그대로 쓰고 있습니다. 그대로 두면 아직 완성되지 않은 사이트처럼 보이고, 우리만의 아이콘으로 바꾸는 순간 완성된 서비스라는 인상을 줍니다.

[개념] 파비콘(favicon)

브라우저 탭, 즐겨찾기, 검색 결과 목록 등에 사이트 로고 대신 표시되는 작은 정사각형 아이콘입니다. 프로젝트 폴더 안의 favicon.ico 파일 하나만 바꾸면 사이트 전체에 반영됩니다.

[비유] 💡 이렇게 생각해 보세요

파비콘은 명함에 박힌 작은 로고예요. 명함 본문을 다 안 읽어도 로고만 보고 "아, 그 회사구나" 하고 기억하잖아요. 탭이 스무 개 열려 있어도 이 작은 아이콘 하나로 내 사이트를 바로 찾아낼 수 있어요.

파비콘을 만드는 가장 쉬운 방법은 https://favicon.io/ 에 접속해서 PNG를 ICO로 바꾸는 것입니다. 저자는 날씨 기반 옷차림 추천 사이트라는 컨셉에 맞춰 GPT에게 우산 모양 이미지를 그려 달라고 요청한 뒤, 그 이미지를 favicon.io에 업로드해 favicon.ico 파일을 받았습니다. 받은 파일을 프로젝트 안의 기존 favicon.ico와 통째로 교체하고, npm run dev로 로컬 서버를 띄운 뒤 localhost:3000에서 탭 아이콘이 바뀌었는지 확인합니다. 잘 바뀌었다면 커밋하고 푸시해서 실제 배포본에도 반영합니다.

[주의] 파일만 바꾸고 캐시를 못 봤다는 착각

파일을 교체하고 새로고침해도 예전 아이콘이 그대로 보일 때가 있습니다. 대부분 파비콘이 안 바뀐 게 아니라 브라우저가 이전 아이콘을 캐시하고 있는 것이므로, 강력 새로고침이나 시크릿 창으로 다시 확인해 보세요.

9.2 Open Graph — 링크로 공유될 때의 얼굴

카카오톡이나 페이스북에 링크를 붙여넣으면 이미지·제목·설명이 담긴 미리보기 카드가 뜹니다. 이 카드가 어떻게 보일지 정하는 규칙이 Open Graph(OG)입니다. 아무 설정이 없으면 미리보기가 텅 비거나 아무 이미지나 잡혀서, 링크를 받은 사람이 클릭할 마음이 줄어듭니다.

[비유] 🔧 이렇게 생각해 보세요

Open Graph는 택배 상자 겉면에 붙는 미리보기 라벨이에요. 상자를 열어보지 않아도 겉면 라벨만 보고 "아, 내가 시킨 그 물건이구나" 하고 알잖아요. 링크도 마찬가지로, 클릭하기 전에 라벨(미리보기 카드)이 사이트의 첫인상을 대신 보여줘요.

Claude Code에게 Open Graph 메타 태그를 넣어 달라고 요청하면 됩니다. 이때 필요한 og-image도 파비콘처럼 GPT에게 이미지 생성을 요청해서 만듭니다. 만든 이미지가 실제로 1200×630 규격인지 반드시 확인하고, 규격이 안 맞으면 https://www.iloveimg.com/ko/resize-image 에서 크기를 맞춘 뒤 og-image라는 이름으로 public 폴더에 넣고 커밋·푸시로 배포합니다.

[AI에게] AI에게 이렇게 시켜보세요

우리 사이트에 Open Graph 메타 태그를 추가해줘. [내 환경] Next.js 프로젝트, public 폴더에 og-image.png(1200x630)를 넣어뒀어. 사이트 주소는 https://내도메인 이야. [하고 싶은 것] - og:title, og:description, og:image, og:url을 head에 넣어줘 - 트위터 카드용 태그도 같이 넣어줘 [꼭 지켜줘] - og:image 경로는 반드시 절대경로(https://내도메인/og-image.png)로 넣어줘 - 상대경로("/og-image.png")는 쓰지 마 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — <meta property="og:image" content="https://내도메인/og-image.png">처럼 og:image 값이 도메인까지 포함한 절대경로로 채워져 있고, 크롤러가 접근할 수 있는 형태로 안내합니다.

[AI 함정] AI가 여기서 틀립니다

AI는 og:image 경로를 페이지 안에서만 통하는 상대경로로 넣는 실수를 자주 합니다. 브라우저로 직접 열어 보면 이미지가 잘 뜨기 때문에 개발자는 문제를 눈치채지 못하지만, 카카오톡·페이스북 크롤러는 페이지 밖에서 접근하므로 상대경로를 도메인 없는 주소로 읽고 이미지를 못 찾습니다.

[X] AI가 준 코드 
<meta property="og:image" content="/og-image.png" />
문제 
· 카카오톡 디버거에서 미리보기 이미지가 안 뜸
· 크롤러가 이미지 주소를 "/og-image.png" 그대로 요청해 실패
[O] 고친 코드 
<meta property="og:image" content="https://내도메인/og-image.png" />

이걸 잡아낸 개념 — 9.2절에서 안내한 카카오·페이스북·트위터 디버거로 실제 미리보기를 확인하는 습관이 이 문제를 잡아냅니다.

설정이 끝났다면 실제로 잘 반영됐는지 도구로 확인합니다. 카카오톡(https://developers.kakao.com/tool/debugger), 페이스북·디스코드(https://developers.facebook.com/tools/debug/), 트위터(https://cards-dev.twitter.com/validator)에 사이트 주소를 넣으면 이미지·제목·설명이 정상적으로 표시되는지 바로 확인할 수 있습니다.

이 장에서 배운 것

  • favicon.io로 favicon.ico를 새로 만들어 기본 아이콘을 교체하는 절차를 익혔습니다.
  • Open Graph 메타 태그와 1200×630 og-image를 절대경로로 넣어 공유 미리보기를 완성했습니다.
  • 카카오·페이스북·트위터 디버거로 실제 미리보기가 정상인지 확인하는 방법을 익혔습니다.

파비콘과 Open Graph는 코드는 작지만, 사이트가 "완성됐다"는 인상을 만드는 첫 번째 브랜딩 작업입니다.

연습문제

1. 브라우저 탭 맨 왼쪽에 표시되는 작은 아이콘을 부르는 이름은 무엇인가요? 쉬움

정답 보기

파비콘(favicon)입니다. 탭·즐겨찾기·검색 결과에 함께 노출되어 사이트를 한눈에 알아보게 해 줍니다.

2. og-image를 만들었는데 카카오톡 미리보기에서 이미지가 잘려 보입니다. 가장 먼저 의심해야 할 것은 무엇인가요? 보통

정답 보기

이미지 규격입니다. og-image는 1200×630 비율을 기준으로 하므로, 이 비율에서 벗어나면 플랫폼마다 이미지가 잘리거나 아예 뜨지 않을 수 있습니다.

3. AI에게 OG 태그 삽입을 맡겼더니 og:image가 "/og-image.png"로 들어갔습니다. 왜 문제이고, 어떻게 고쳐야 하나요? 어려움

정답 보기

브라우저에서는 상대경로도 잘 열리지만, 카카오톡·페이스북 크롤러는 페이지 밖에서 접근하기 때문에 도메인이 포함된 절대경로(https://내도메인/og-image.png)가 필요합니다.
