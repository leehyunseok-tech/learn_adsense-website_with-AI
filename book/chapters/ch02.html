우리가 만들 사이트의 뼈대 이해하기

이번 장에서는 우리가 실제로 만들 사이트, 날씨 기반 옷차림 추천 사이트의 뼈대를 먼저 이해합니다. 서버 없이도 완성된 사이트를 만드는 방법을 그림으로 확인합니다.

약 14분 예제 0개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • 웹사이트 구조를 난이도에 따라 네 가지로 구분할 수 있습니다.
  • 날씨 옷차림 추천 사이트의 네 조각(Claude Code·Cloudflare·Supabase·WeatherAPI)이 어떻게 손발을 맞추는지 설명할 수 있습니다.

2.1 서비스 구조 네 가지 패턴

웹사이트라고 다 같은 난이도는 아닙니다. 무엇을 담느냐에 따라 크게 네 가지 구조로 나눌 수 있고, 구조가 복잡해질수록 만들고 유지하는 부담도 함께 커집니다.

구분구성설명난이도
① 화면만 있는 사이트 Frontend만 데이터 저장이 필요 없는 형태. 예: 계산기, PDF 변환기, 이미지 리사이즈 툴 ★☆☆☆☆
② 화면 + 외부 데이터를 불러오는 사이트 Frontend + 서버리스 + 외부 데이터 직접 서버를 만들지 않아도 자동으로 외부 데이터를 불러와 보여주는 방식. 예: 날씨 정보, 환율 정보 ★★☆☆☆
③ 직접 서버를 운영하는 사이트 Frontend + 서버 + 외부 데이터 내 서버를 직접 운영해서 데이터를 불러오거나 가공해 보여주는 방식. 예: 뉴스 요약, 게임 전적 ★★★★☆
④ 직접 서버를 운영하면서 데이터를 저장하는 사이트 Frontend + 서버 + 데이터베이스 사용자의 글이나 정보가 저장되는 서비스. 예: 회원가입, 게시판, 댓글 ★★★★★

[개념] 서버리스(Serverless)

내가 직접 서버를 켜 두지 않아도, 요청이 올 때만 코드가 잠깐 실행되고 사라지는 방식으로 서버 역할을 대신하는 환경입니다.

[비유] 💡 이렇게 생각해 보세요

네 가지 구조는 집 규모를 늘려가는 것과 비슷해요. ①은 원룸 자취(화면만 있으면 됨), ②는 배달 음식 시켜먹기(필요할 때만 외부에서 가져옴)예요.

③은 직접 요리해서 차려내는 살림, ④는 손님을 계속 받고 재고까지 관리하는 레스토랑 운영이에요. 규모가 커질수록 챙길 게 많아져요.

[주의] 처음부터 ④번부터 시작하는 함정

회원가입과 게시판부터 갖추려 하면 서버 운영과 데이터베이스 관리까지 한꺼번에 떠안게 됩니다. 이 책은 접근성이 좋은 ②번 구조부터 완주한 뒤, 필요할 때 ③④로 넓혀가는 순서를 권합니다.

2.2 이번에 만들 사이트 — 날씨 기반 옷차림 추천

이 책에서 실제로 만드는 사이트는 날씨 기반 옷차림 추천 사이트입니다. 사용자가 접속하면 오늘 날씨를 자동으로 가져와 "오늘은 이렇게 입으세요"라고 알려주는 도구형 서비스입니다. 회원가입도, 데이터베이스도 없는 2.1절의 ②번 구조로 만듭니다.

[비유] 🔧 이렇게 생각해 보세요

Cloudflare는 우리가 만든 웹사이트를 올려놓는 사이트 전시장 같은 곳이에요.

파일을 전시장에 가져다 두기만 하면, 누구든 그 전시장 주소로 들어와 구경할 수 있어요.

[AI에게] AI에게 이렇게 시켜보세요

날씨 기반으로 오늘 뭘 입을지 추천해주는 사이트를 만들려고 해. [내 환경] - Claude Code로 화면을 만들 예정 - 서버를 직접 운영하고 싶지 않음 - 데이터베이스도 쓰고 싶지 않음 [하고 싶은 것] 사용자가 접속하면 자동으로 오늘 날씨를 가져와서 옷차림을 추천해주는 구조를 설계해줘. [꼭 지켜줘] - 회원가입, 게시판 같은 기능은 필요 없음 - 배포는 Cloudflare를 쓸 계획임 - 날씨 데이터는 WeatherAPI.com에서 가져올 거야 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — 회원가입이나 DB 없이, Cloudflare에 화면을 올리고 Supabase Edge Function 같은 서버리스 조합으로 외부 API를 호출하는 구조를 제안하면 정상입니다.

[AI 함정] AI가 여기서 틀립니다

"사이트 어떻게 만들어?"처럼 구조 조건을 안 주고 물으면 AI는 습관적으로 회원가입과 데이터베이스가 있는 ④번 구조부터 제안합니다. 단순 조회 기능에는 과한 구조입니다.

2.3 네 조각이 손발을 맞추는 순서

사용자가 브라우저로 웹사이트에 접속하면, 다음 다섯 단계로 네 조각이 순서대로 움직입니다.

  1. Claude Code로 만든 웹사이트를 Cloudflare에 올립니다(배포).
  2. Cloudflare에 올라간 웹사이트가 Supabase Edge Function을 호출합니다.
  3. Supabase Edge Function이 WeatherAPI에 날씨를 물어봅니다.
  4. WeatherAPI가 응답한 날씨 데이터가 Edge Function을 거쳐 되돌아옵니다.
  5. 그 결과가 사용자 화면에 옷차림 추천으로 표시됩니다.

네 조각은 각자 맡은 역할이 뚜렷하게 나뉘어 있어, 하나가 문제를 일으켜도 나머지에 영향을 덜 줍니다. 아래 표로 각 조각의 역할과 목적을 한 번에 정리합니다.

역할하는 일목적
Claude Code (개발 도구) 터미널에서 대화하듯 코드를 작성하는 도구 사이트 디자인하고 기능 넣기
Cloudflare (배포 플랫폼) 만든 사이트를 세상에 공개(배포) 누구나 접속 가능하게 만들기
Supabase Edge Function (서버 역할) 외부 서비스에 요청 서버 없이도 날씨 가져오기
WeatherAPI.com (외부 데이터) 실제 날씨 데이터 제공 "서울: 맑음, 15°C" 반환

이 장에서 배운 것

  • 웹사이트 구조는 난이도에 따라 ①화면만 ②화면+외부 데이터 ③직접 서버 ④서버+DB 네 가지로 나뉩니다.
  • 이 책은 접근성이 좋은 ②번 서버리스 구조로, 날씨 기반 옷차림 추천 사이트를 만듭니다.
  • 사용자 → Cloudflare → Supabase Edge Function → WeatherAPI.com 순서로 요청이 흐르고, 결과가 다시 화면까지 돌아옵니다.

우리는 서버도 DB도 없이, 네 조각이 순서대로 손발을 맞추는 구조로 사이트를 만듭니다.

연습문제

1. 이 책이 만드는 날씨 옷차림 추천 사이트는 서비스 구조 네 가지 중 몇 번에 해당하나요? 쉬움

정답 보기

②번, 화면 + 외부 데이터를 불러오는 사이트입니다. 회원가입이나 데이터베이스 없이 서버리스 구조로 외부 날씨 데이터를 불러옵니다.

2. Supabase Edge Function은 이번 아키텍처에서 어떤 역할을 맡나요? 보통

정답 보기

내 서버를 직접 켜 두지 않고도 WeatherAPI.com에 날씨를 요청하는 서버 역할을 대신합니다. 요청이 올 때만 실행되는 서버리스 방식입니다.

3. 단순 조회 기능만 필요한데도 AI가 회원가입과 DB가 있는 ④번 구조를 먼저 제안한다면, 어떻게 다시 물어야 할까요? 어려움

정답 보기

"회원가입도 DB도 없이, 접속할 때마다 최신 데이터만 보여주면 충분하다"는 조건을 명시해서 다시 설계해 달라고 요청합니다. 그러면 서버리스(②번) 구조로 답을 고쳐 줍니다.
