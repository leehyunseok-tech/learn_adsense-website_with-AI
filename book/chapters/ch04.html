Node.js와 Cloudflare로 배포 준비 끝내기

이 장에서는 사이트를 실제로 움직이게 하는 두 가지 준비를 마칩니다. Node.js와 npm으로 로컬에서 사이트를 띄워 보고, Cloudflare로 인터넷에 자동으로 배포되는 통로를 뚫습니다. 이 장을 마치면 코드를 Github에 push하는 순간 사이트가 실제로 업데이트됩니다.

약 15분 예제 2개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • Node.js와 npm을 설치하고 PowerShell 실행 정책을 허용할 수 있다.
  • npm install과 npm run dev로 로컬에서 사이트를 직접 띄워 볼 수 있다.
  • Cloudflare 계정을 만들어 Github 저장소와 연결하고 자동 배포를 설정할 수 있다.

4.1 Node.js와 npm 설치하기

npm은 Node Package Manager의 줄임말로, 사이트를 만들 때 필요한 재료들을 가져오는 프로그램입니다. npm 명령어를 실행하려면 먼저 Node.js를 설치해야 합니다.

[개념] Node.js와 npm

Node.js는 브라우저 밖에서 자바스크립트를 실행하는 프로그램이고, npm은 그 위에서 필요한 코드 재료(패키지)를 내려받아 관리하는 도구입니다.

[비유] 💡 이렇게 생각해 보세요

npm은 재료를 배달해주는 택배기사라고 생각하면 편해요. 요리를 하려면 장을 봐야 하듯, 사이트를 만들려면 이미 누군가 만들어 둔 코드 재료가 필요해요. npm install이라고 한 번 외치면, 필요한 재료들을 전부 문 앞까지 배달해 줘요.

설치 순서는 다음과 같습니다.

  1. https://nodejs.org/ko/download 에서 본인 운영체제에 맞는 설치 파일을 내려받아 설치합니다.
  2. 윈도우 사용자는 터미널을 열고 아래 명령어로 PowerShell 스크립트 실행 정책을 허용합니다.
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

[주의] PowerShell 실행 정책을 그대로 두는 함정

윈도우 PowerShell은 기본적으로 외부 스크립트 실행을 막아 두므로, 이 명령어를 실행하지 않으면 npm install 같은 명령이 권한 오류로 조용히 막힙니다. 한 번만 허용해 두면 이후 실습에서는 다시 신경 쓸 필요가 없습니다.

4.2 로컬에서 사이트 띄워보기 — npm run dev

Node.js 설치를 마쳤다면, 이제 터미널에서 실제로 사이트를 띄워 볼 차례입니다. 터미널을 열면 지금 어느 폴더에 있는지부터 확인해야 합니다.

[비유] 🔧 이렇게 생각해 보세요

npm run dev는 손님을 받기 전 리허설과 같아요. 진짜 무대(인터넷)에 올리기 전에, 내 컴퓨터라는 연습실에서 실제로 화면이 잘 나오는지 미리 확인해 보는 거예요.

pwd 명령어로 현재 작업 위치 경로를 확인할 수 있습니다. 3장에서 만든 repository 위치에 있을 수 있으므로, cd 명령어로 skeleton 폴더로 이동해야 합니다. cd ske까지 입력하고 탭 키를 누르면 자동완성됩니다. 

pwd
cd ske  # 탭 키를 누르면 폴더 이름이 자동완성됩니다

폴더를 옮겼다면, 필요한 재료를 설치하고 개발 서버를 실행합니다.

npm install
npm run dev

https://localhost:3000 에 접속했을 때 화면이 보이면, 개발 서버 구동이 성공적으로 된 것입니다.

[AI에게] AI에게 이렇게 시켜보세요

이 에러 로그를 보고 원인을 알려줘. [내 환경] 터미널에서 npm run dev를 실행했는데 서버가 뜨지 않고 아래 에러가 떴어. [에러 로그] (여기에 터미널에 뜬 에러 메시지를 그대로 붙여넣기) [하고 싶은 것] 왜 이 에러가 나는지, 어떤 명령어를 다시 실행해야 하는지 순서대로 알려줘. [꼭 지켜줘] - 폴더 위치나 설치 순서 문제일 가능성부터 먼저 확인해줘 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — 엉뚱한 폴더에서 명령어를 실행했거나 npm install을 건너뛰었을 가능성을 먼저 짚어 주고, pwd로 위치를 확인한 뒤 다시 실행해 보라고 안내합니다.

4.3 Cloudflare 계정 만들고 자동 배포 연결하기

Cloudflare(클라우드플레어)는 내가 만든 사이트를 전 세계 어디서든 빠르고 안전하게 보여주는 서비스입니다. 단순히 사이트를 올려주는 공간이 아니라, 한 번만 연결해두면 코드를 수정할 때마다 자동으로 사이트가 업데이트되는 자동 배포 시스템을 제공합니다.

[비유] 🌍 이렇게 생각해 보세요

Cloudflare는 내가 만든 사이트를 세상에 선보이는 전시장 같아요. 작품(코드)을 완성해서 Github에 올려두기만 하면, 전시장이 알아서 매번 새 버전으로 진열을 바꿔 줘요. 방문객(사용자)이 어디에 있든 가장 가까운 전시장 지점에서 빠르게 볼 수 있게 해줘요.

설정 순서는 다음과 같습니다.

  1. Cloudflare에 회원가입하거나 로그인합니다.
  2. 컴퓨팅(Workers) 혹은 컴퓨팅 및 AI에서 "Workers 및 Pages"를 클릭합니다.
  3. "응용 프로그램 생성" 버튼을 누르고 "리포지토리 가져오기 시작"을 선택합니다.
  4. "새로운 Github 연결"로 3장에서 만든 repository와 연결합니다.
  5. 프로젝트 이름을 원하는 대로 정합니다.
  6. "빌드 및 배포 명령"을 올바르게 입력한 뒤 "생성 및 배포"를 클릭합니다.

이후 이 프로젝트는 commit, push할 때마다 자동으로 사이트에 변경사항이 반영됩니다. 3장에서 배운 commit, push 습관이 여기서 그대로 이어집니다.

[AI 함정] AI가 여기서 틀립니다

Cloudflare가 자동으로 채워주는 빌드 명령을 확인 없이 그대로 두거나 오타를 낸 채 생성 및 배포를 누르면, 배포 로그에는 에러가 남지만 화면에서는 아무 변화도 보이지 않아 원인을 찾기 어렵습니다.

이걸 잡아낸 개념 — 4.2절에서 확인한 npm run build의 역할입니다. Cloudflare의 빌드 명령은 결국 내 컴퓨터에서 실행했던 것과 같은 명령이어야 합니다.

이 장에서 배운 것

  • Node.js와 npm을 설치하고 PowerShell 실행 정책을 허용했다.
  • npm install과 npm run dev로 로컬에서 사이트를 직접 띄워 봤다.
  • Cloudflare 계정을 만들어 Github 저장소와 연결하고 자동 배포를 설정했다.

npm은 재료를 가져오는 도구이고, Cloudflare는 그 결과물을 세상에 보여주는 자동 전시장입니다.

연습문제

1. PowerShell에서 Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser 명령어는 왜 실행해야 하나요? 쉬움

정답 보기

윈도우 PowerShell은 기본적으로 외부 스크립트 실행을 막아 두기 때문입니다. 이 명령어로 실행 정책을 허용하지 않으면 npm install 같은 명령이 권한 오류로 막힙니다.

2. npm run dev와 npm run build는 각각 언제 사용하는 명령어인가요? 보통

정답 보기
