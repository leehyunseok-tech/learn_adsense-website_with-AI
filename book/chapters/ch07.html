7

도메인 사서 내 사이트에 연결하기

지금까지는 weather-app.사용자ID.workers.dev 같은 임시 주소로만 사이트를 확인했습니다. 이 장에서는 직접 도메인을 구매하고 Cloudflare에 연결해, 진짜 내 주소로 사이트를 여는 법을 배웁니다.

약 20분 예제 1개 연습문제 3문항

이 장을 끝내면 할 수 있는 것

  • 도메인을 왜 구매해야 하는지, 어떤 확장자를 고르면 좋은지 판단할 수 있습니다.
  • 가비아에서 도메인을 구매하고 Cloudflare에 온보딩할 수 있습니다.
  • 네임서버를 Cloudflare 쪽으로 바꾸고, 배포한 사이트에 커스텀 도메인을 연결할 수 있습니다.

7.1 도메인, 꼭 사야 할까

Cloudflare가 기본으로 주는 주소는 https://weather-app.사용자ID.workers.dev/처럼 생겼습니다. 이 주소로도 서비스는 문제없이 돌아갑니다. 다만 겉보기에 다소 조잡해 보이고, 방문자 입장에서는 신뢰도가 떨어져 보일 수 있습니다.

짧고 기억하기 쉬운 도메인은 방문자의 신뢰를 높여줍니다. 특히 광고 수익형 사이트나 개인 브랜드 사이트는 도메인이 첫인상을 좌우합니다. 전 세계 대부분의 사용자가 .com으로 끝나는 도메인을 가장 익숙하게 받아들입니다.

[개념] 도메인

사람이 외우기 쉬운 문자열로, 실제로는 서버의 숫자 주소(IP)를 대신 가리키는 인터넷 상의 이름입니다.

[비유] 💡 이렇게 생각해 보세요

도메인은 .com이라는 번지수가 적힌 문패예요. workers.dev 주소가 "OO동 OO번지, 3층 임시 사무실"이라면, 내 도메인은 "정식으로 문패를 단 우리 가게"인 셈이에요. 방문자는 문패가 있는 가게를 훨씬 더 믿고 들어와요.

.net, .info, .site 같은 확장자도 쓸 수 있지만, .com은 "정식 사이트"라는 인상을 줘서 클릭률이 더 높은 편입니다. 국내에서는 가비아(Gabia)를 통해 쉽게 구매할 수 있습니다.

[주의] 사용 기한을 길게 잡는 함정

첫 구매 시에는 도메인 사용 기한을 1년으로 하는 것이 할인율이 가장 큽니다. 몇 년 치를 미리 끊어두기보다, 사이트 이용률이 괜찮은지 확인한 뒤 나중에 연장하는 편이 안전합니다.

7.2 가비아에서 도메인 구매하기

가비아에서 원하는 도메인을 검색해 구매를 마치면, My가비아 → 이용 중인 서비스 → 도메인 → 관리 순서로 들어가 도메인을 관리할 수 있습니다. 이 화면이 앞으로 네임서버를 바꿀 때 다시 찾아올 곳입니다.

도메인 구매가 끝났다고 곧바로 사이트가 연결되는 것은 아닙니다. Cloudflare 대시보드(dash.cloudflare.com)에서 이 도메인을 온보딩하는 절차를 거쳐야 합니다.

[비유] 🔧 이렇게 생각해 보세요

네임서버를 바꾸는 건 우편물을 옛 주소에서 새 주소로 돌리는 전입신고예요. 가비아라는 옛 동네에 살던 도메인을, "이제부터는 Cloudflare 동네에서 우편물을 받을게요"라고 신고하는 거예요. 신고가 처리될 때까지는 약간 시간이 걸려요.

Cloudflare에서 "도메인 온보딩" 버튼을 누르고 구매한 도메인 주소를 입력합니다. 이때 크롤러는 반드시 허용해야 합니다. 구글 애드센스나 검색엔진의 크롤러가 사이트를 방문할 수 있어야 하기 때문입니다. 요금제는 Free로도 충분합니다.

[AI에게] AI에게 이렇게 시켜보세요

Cloudflare에 커스텀 도메인을 새로 연결했어. 사이트 코드에서 도메인 주소를 참조하는 부분이 다 새 도메인 기준으로 맞는지 점검해줘. [내 환경] - 기존 주소: weather-app.내ID.workers.dev - 새 도메인: 내가산도메인.com [하고 싶은 것] - canonical 태그, sitemap.xml, robots.txt, 메타데이터 등 사이트 안에서 절대 주소를 쓰는 부분을 모두 찾아서 새 도메인 기준으로 맞는지 확인해줘. - workers.dev 주소가 남아 있는 곳이 있으면 알려줘. [꼭 지켜줘] - 값을 바꾸기 전에 어떤 파일의 어떤 줄을 왜 바꾸는지 먼저 설명해줘. 마지막에 위험한 곳을 짚어줘.

이런 답이 오면 정상 — canonical 태그와 sitemap.xml 안의 주소가 모두 새 도메인으로 통일되어 있고, workers.dev 주소가 남아있는 곳을 구체적으로 짚어줍니다.

[AI 함정] AI가 여기서 틀립니다

커스텀 도메인을 연결해도 workers.dev 기본 주소는 그대로 살아있습니다. AI에게 "도메인 연결해줘"라고만 요청하면 이 사실을 놓치고, 두 주소가 동시에 접속 가능한 상태를 그냥 두는 경우가 많습니다. 둘 다 접속은 잘 되기 때문에 눈으로는 문제를 알아채기 어렵습니다.

[X] AI가 준 설정 
커스텀 도메인(내가산도메인.com)만 추가하고 끝냄
→ weather-app.내ID.workers.dev 도 그대로 접속 가능
→ 검색엔진이 두 주소를 서로 다른 사이트로 인식
문제 
· 같은 콘텐츠가 두 주소로 중복 노출됨
· 검색엔진이 어느 쪽을 정식 주소로 볼지 헷갈려 순위가 흩어짐
[O] 고친 설정 
커스텀 도메인을 정식 주소로 지정
→ workers.dev 주소로 들어오면 내가산도메인.com 으로
  301 리다이렉트 되도록 설정
→ canonical 태그도 내가산도메인.com 으로 통일

이걸 잡아낸 개념 — 7.3절에서 다루는 "도메인은 하나의 정식 주소로 정리해야 한다"는 원칙입니다.

7.3 Cloudflare 네임서버로 갈아타기

Cloudflare에서 도메인 온보딩을 마치면 dash.cloudflare.com 화면에 "잘못된 이름 서버"라는 안내가 보입니다. 우리가 구매한 도메인의 네임서버가 아직 가비아 것으로 되어 있으니, Cloudflare의 네임서버로 바꿔야 한다는 뜻입니다.

가비아로 돌아가 도메인 관리에서 네임서버 설정 버튼을 누르고, 네임서버를 Cloudflare가 안내해준 주소로 바꿉니다. 소유자 인증을 마친 뒤 적용 버튼을 누르면 변경이 시작됩니다.

다시 Cloudflare로 돌아와 "지금 이름 서버 확인" 버튼을 누릅니다. 보통 3~5분 정도면 활성 상태로 바뀝니다. 활성화되면 사이드바의 Workers 및 Pages → 배포한 사이트 → 도메인 및 경로 → 추가 → 사용자 설정 도메인 순서로 들어가 구매한 도메인을 입력하고 "도메인 추가" 버튼을 누르면, 이제 그 도메인으로 접속했을 때 우리가 만든 서비스로 연결됩니다.

이 장에서 배운 것

  • workers.dev 임시 주소 대신 .com 도메인을 사는 이유와 장점을 정리했습니다.
  • 가비아에서 도메인을 구매하고 Cloudflare에 온보딩하며 크롤러 허용을 확인했습니다.
  • 가비아의 네임서버를 Cloudflare 것으로 바꾸고, 배포한 사이트에 커스텀 도메인을 연결했습니다.

도메인은 신뢰의 문패이고, 네임서버 변경은 그 문패로 우편물을 돌리는 전입신고입니다.

연습문제

1. workers.dev 기본 주소가 있는데도 굳이 도메인을 따로 사는 이유는 무엇인가요? 쉬움

정답 보기

기본 주소는 겉보기에 조잡해 보이고 신뢰도가 낮아 보일 수 있습니다. 짧고 기억하기 쉬운 도메인, 특히 .com은 방문자의 신뢰를 높이고 광고 수익형·개인 브랜드 사이트의 첫인상을 좌우합니다.

2. Cloudflare에서 도메인을 온보딩할 때 "크롤러 허용"을 반드시 켜둬야 하는 이유는 무엇인가요? 보통

정답 보기

크롤러를 차단하면 구글 애드센스나 검색엔진의 크롤러도 함께 막혀 사이트를 방문할 수 없게 됩니다. 애드센스 심사와 검색 노출 모두 크롤러가 사이트를 읽을 수 있어야 가능합니다.

3. 커스텀 도메인을 연결한 뒤에도 workers.dev 주소를 그대로 열어두면 어떤 문제가 생기고, 어떻게 고쳐야 하나요? 어려움

정답 보기

같은 콘텐츠가 두 주소로 동시에 노출되어 검색엔진이 정식 주소를 헷갈려 순위가 흩어질 수 있습니다. workers.dev 주소는 커스텀 도메인으로 리다이렉트하고, canonical 태그도 커스텀 도메인으로 통일해야 합니다.
